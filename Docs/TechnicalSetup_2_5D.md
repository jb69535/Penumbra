# Penumbra 3D/2.5D Technical Setup

Penumbra uses a 3D Unity project setup for the Hollow Knight-style target, while keeping gameplay on a 2D plane.

The recommended setup is:

- Unity default behavior mode: 3D.
- URP default renderer: Universal Renderer.
- 2D physics for player, enemies, hitboxes, hurtboxes, platforms, and triggers.
- Orthographic side-view camera.
- SpriteRenderers and flat art planes placed in 3D space.
- Visual depth through sorting layers, Z placement, foreground masks, and parallax.
- Optional 3D meshes for set dressing, lighting blockers, and background architecture.

This gives the production benefits of a 3D Unity scene while keeping movement and combat precise.

## Why Not 3D Gameplay

Do not turn player movement into free 3D movement. Full 3D gameplay would make platforming, melee ranges, hit reactions, enemy AI, and level blocking more expensive to tune. It also adds depth-axis bugs that do not help a Hollow Knight-like game.

Use 3D physics only if the game design truly needs the player to move into and out of the screen. Penumbra does not need that for the current design.

## Gameplay Plane

Gameplay happens on the XY plane.

- X: horizontal movement.
- Y: jumping, falling, vertical level design.
- Z: visual depth, parallax, and set dressing.

Player movement, attacks, and collisions should use `Rigidbody2D`, `Collider2D`, `Physics2D`, and 2D trigger volumes.

If a visual platform is a 3D mesh or sprite plane, give it a matching 2D collider for gameplay.

## Visual Stack

Use these sorting layers from back to front:

- `Background Far`
- `Background Mid`
- `Environment`
- `Gameplay`
- `Foreground`
- `VFX`
- `UI`

The project transparency sort axis is set to Z, so Z placement can help organize depth. Sorting layers and sorting order should still be the primary ordering tool for character and environment art.

## Sample Scene

Open `Assets/Penumbra/Scenes/Sandboxes/Sandbox_Movement2D.unity`.

It demonstrates:

- A capsule main character with 2D movement, double jump, dash, a sample chain attack, and hit motion.
- Orthographic follow camera.
- Background and foreground depth bands.
- Parallax layers that move at different speeds from the camera.
- Standard 3D directional light.
- A hit-motion test pad.

Controls:

- `A` / `D` or arrow keys: move.
- `Space`: jump / double jump.
- `Shift`: dash.
- `J`: sample chain attack.
- `H`: force a test hit reaction.

The main playable prototype is `Assets/Penumbra/Scenes/Prototype_Cave.unity`. It is regenerated by `Tools > Penumbra > Rebuild Prototype Vertical Slice` and should contain the first GDD loop: movement, one readable enemy, light/shadow state switching, and one keyboard-aimed mirror receiver puzzle.

## When To Use 3D Assets

3D assets are encouraged for background set dressing, animated props, large cave forms, particles, lighting tricks, and depth silhouettes. Keep them on non-gameplay layers unless they intentionally block the player through separate 2D colliders.

If a 3D mesh visually represents a platform, create a matching 2D collider for gameplay. Do not rely on MeshCollider for player movement unless the whole movement model is intentionally redesigned.

## Import Notes

Because the project default behavior mode is 3D, imported images may need their Texture Type set to `Sprite (2D and UI)` before they can be used as SpriteRenderers. That is intentional: the project behaves like a 3D scene setup, while selected assets become sprites where needed.
